MIGRATION: WHAT COMES OVER
==========================
This is a port of an existing application, not a restart from zero.

Copy/reuse, with configuration/schema review:
* Source and Git history, docs, Python business logic, browser HUD assets/tests.
* Vault notes, Tasks.md, generated documents and project repositories.
* Facts/recent memory, handoffs, routine definitions, response/privacy preferences,
  reminders, digest definitions/reports and relevant agent history from data/.
  Inspect actual filenames rather than inventing or dropping unknown stores.
* Voice recordings, voice profile, voice identity/enrollment data and model weights.
  Weights/recordings are generally reusable; runtime compatibility and microphone
  changes may require adjustments or owner re-enrollment. Do not guarantee this.
* Local model blobs/manifests if compatible with the installed Linux runtime;
  otherwise re-download the same verified model revision. Rebuild search caches
  when paths/model identities change rather than assuming Windows indices fit.

Recreate or adapt:
* .venv and all compiled packages: create a Linux virtual environment. Do not copy
  Windows Python executables or DLLs and expect them to run. Split platform-specific
  dependencies out of requirements.txt and choose supported Linux builds.
* Ollama/other executables, GPU stack, launchers/startup registration, device IDs,
  fonts, paths, shortcuts, shell syntax, terminal integration and permissions.
* Windows-specific desktop, activity, audio, credentials and automation backends.
* DPAPI-encrypted credentials: Linux cannot simply decrypt the Windows stores.
  Prefer fresh sign-ins / newly entered keys into a Linux secret-service backend.
  Never put decrypted credentials into a Git handoff or ordinary transfer manifest.
* Provider sessions/auth state may require new sign-in. Existing provider integration
  is not a promise that another provider accepts the same account/session format.
