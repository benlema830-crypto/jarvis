WHAT EACH STEP DOES
A file backup copies personal files to another physical disk or verified cloud
storage. It does not automatically preserve an immediately bootable Windows
installation, installed applications, or every Windows-protected credential.
A full system image is a separate, larger backup option for restoring Windows
and its partitions; it needs a suitable image tool and working recovery media.
Partitioning reduces the space assigned to Windows and creates unallocated
space for Linux. It changes the disk layout and needs a verified backup first.
A live USB test starts Fedora without installing; no resize is needed to try it.
Keep the Windows disk unmodified during the live test.

BACKUP EXECUTION AND VERIFICATION (PENDING DESTINATION)
1. Identify destination physical disk/account and confirm available capacity.
   A folder or second partition on the same Windows SSD is not independent.
   Do not format a destination that already holds files.
2. Choose file backup versus an additional full Windows system image. Make the
   exact coverage clear before calling the PC backed up.
3. Create a dated, new destination folder. Copy rather than move; no mirror
   deletion or purge options. Handle junctions without recursive loops and
   download or independently verify cloud-only files.
4. Coordinate active writers, consistent database snapshots and locked files.
5. Record source/destination counts, lengths, errors and omitted files. Verify
   SHA-256 for irreplaceable project/data/voice files and restore a selection
   into a temporary folder to confirm they open. Treat any mismatch as pending.
6. Keep the backup disconnected during installation where practical. Confirm
   Windows recovery options and account access before disk changes.

FEDORA INSTALLATION REVIEW (AFTER LIVE TEST)
Use only the prepared unallocated space on the internal MSI SSD. The USB is
installation media, not the destination. Keep Windows partitions intact.
Let Fedora propose its Linux boot/filesystem layout, then inspect the exact
change summary before committing. Btrfs root/home can share free capacity;
there is no need to guess separate fixed home/root sizes now.

The existing EFI partition is only 100 MiB. Verify available EFI space and the
actual installer's requirements before reusing it. If Fedora requires a larger
EFI partition, plan a separate Fedora EFI partition inside the new free space
and review firmware boot entries. Do not enlarge/move/format the Windows EFI
partition as an improvised workaround. A shared EFI, if accepted, must retain
Windows files and must not be formatted. Boot files/entries may be added.

Stop and review if the installer proposes erasing the disk, deleting Windows
or Recovery, formatting the existing EFI, or reclaiming unexpected partitions.
Do not change storage-controller mode or disable Secure Boot as a guessed fix.
Review Windows Fast Startup/hibernation before enabling shared NTFS writes.
After installing, boot both Windows and Fedora and verify files and devices.
